# Печать через ККТ АТОЛ

Для новых методов нужен Go-сервис `fptr_go` с маршрутами `/printer_info` и `/print`. Обновление исходников Rust само по себе не обновляет запускаемый бинарник `libs/kkt`: его нужно собрать и поставить обычным способом проекта.

```rust
use corex_payment::kkt::{Kkt, PrintTask, PrintItem, PrintAlignment, PrintTextSize, QrCorrection};

async fn print_order(kkt: &Kkt) -> Result<(), corex_payment::ProcessError> {
    let info = kkt.printer_info().await?;
    println!("Ширина: {:?}", info.data.width_pixels);

    let task = PrintTask {
        items: vec![
            PrintItem::Text {
                text: "ЗАКАЗ № 123".into(),
                alignment: Some(PrintAlignment::Center),
                bold: true,
                size: Some(PrintTextSize::Large),
            },
            PrintItem::Qr {
                data: "https://example.org/order/123".into(),
                alignment: None,
                module_size: Some(4),
                correction: Some(QrCorrection::M),
            },
        ],
    };
    let result = kkt.print(&task).await?;
    for change in result.data.adaptations {
        println!("Элемент {}: {}", change.item_index, change.description);
    }
    Ok(())
}
```

Для готового PNG/JPEG используйте `PrintItem::Image { data: base64_string, alignment: None, width: None }`. Поле `data` содержит стандартный base64 без префикса `data:`. Путь к файлу и URL не поддерживаются.

Фискальный чек создаётся существующим `payment()` или `refund()` с `SellTask.electronically = false`. `print()` создаёт только нефискальный документ; он не заменяет фискализацию. `document()` читает ФН и не печатает копию.

Подготовкой занимается Go-сервис: штатный текст, растровый вывод оформления/изображений и QR, переносы, масштабирование и проверка возможностей. QR сейчас использует растровый резервный путь, чтобы сохранить заданную коррекцию и поля. Ширина неизвестной модели не угадывается; несовместимый драйвер или неподходящий контент дают ошибку. Полный контракт и ограничения описаны в `../fptr_go/PRINTING.md`.

Необязательные поля задания сериализуются без `null`. Выравнивание текста по умолчанию левое, изображения/QR — по центру. Текст: обычный/большой, жирный/обычный. QR: коррекция M, модуль 4 пикселя, допускается уменьшение до 2. Лимит тела 8 MiB, 256 элементов, 16384 байта текста на элемент; изображения PNG/JPEG до 4 миллионов пикселей, суммарный растр до 4 миллионов пикселей. ККТ может добавить собственный подвал.

Новые методы возвращают существующие `ProcessSuccess<T>` и `ProcessError`. Для ошибки структурированные сведения сохранены в `raw_data`:

```rust
// В ветке Err(error):
// let details: PrintFailure = serde_json::from_value(error.raw_data.clone())?;
// details.state: NotStarted | PossiblyPartial | Unknown
```

`input_data` не содержит изображение или исходное задание. При потере HTTP-ответа/таймауте результат считается `Unknown`; автоматических повторов нет. Таймаут нового запроса — 120 секунд, соединения — 5 секунд. Ошибка получения ответа не означает, что чек не напечатался: проверьте ККТ перед повтором.

`Printed` означает успешный ответ драйвера и последующую проверку состояния, а не визуальную проверку отпечатка. Совместимость схем проверена с ДККТ 10.10.7.0; физическая печать и читаемость QR на конкретной модели требуют проверки с оборудованием.

## Проверка на реальном оборудовании и ИТС

13 ноября 2026 года пользователь подтвердил успешную печать тестового документа с оформленным текстом, QR и PNG на АТОЛ 35Ф по USB: драйвер 10.10.7.0, версия ПО из запроса драйвера 5.11.1, ширина 384 пикселя / 42 символа.

На АТОЛ 27Ф (576 пикселей / 48 символов) вместо содержимого вышло сообщение «Нефискальная печать доступна только по подписке ИТС». Драйвер при этом вернул успех, а API — `printed`. Это известное ограничение текущей реализации: `printed` не гарантирует отсутствие подмены содержимого лицензионным уведомлением. Наличие лицензии №17 также оказалось недостаточным: ККТ сообщила, что она введена и действует до 2098 года. Автоматическое надёжное обнаружение этой блокировки пока не реализовано.

Для эксплуатации необходимо проверить действующую подписку ИТС и выполнить контрольную печать. При таком уведомлении обратитесь к обслуживающему партнёру АТОЛ; повторная отправка задания не устраняет ограничение. Официальное описание ограничения: https://www.atol.ru/company/news/kassy-atol-gotovy-k-rabote-s-novoy-stavkoy-nds-22-/
