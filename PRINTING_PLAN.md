# Реализация печати ККТ

> Для исполнителя: выполнять по superpowers:executing-plans, с проверками до и после реализации.

**Цель:** добавить определение возможностей и печать обычных документов в Go/Rust, сохранив фискальную печать.
**Архитектура:** Go подготавливает элементы, проверяет JSON драйвером до исполнения и сериализует доступ к устройству. Rust предоставляет типизированный контракт и сохраняет ошибки.
**Технологии:** Go, АТОЛ ДККТ 10, image/png/jpeg, golang.org/x/image (встроенные Go fonts с кириллицей, растеризация), go-qrcode; Rust serde/reqwest.
**Дизайн:** PRINTING_DESIGN.md, согласован пользователем.

## Общие ограничения

- Работать в существующих каталогах, без коммитов и внешних изменений. Сохранить исходные пользовательские правки.
- Основной исполнитель работает в текущем чате. Пользователь явно поручил приступить к реализации: повторное согласование плана не требуется.
- Проверять JSON-поддержку средствами установленного драйвера; не делать пробную печать. Прямой Native API для исполнения не вводить без отдельного согласования.
- Не подставлять предполагаемую ширину. Не повторять документ после возможного начала печати.
- Ограничения нового API: тело 8 MiB, 256 элементов, строка 16384 байта, декодированное изображение 4 миллиона пикселей, подготовленный документ 4 миллиона растровых пикселей, ширина устройства до 4096 пикселей, до 4096 подготовленных элементов. Изображения PNG/JPEG. Размер QR-модуля 2..16, по умолчанию 4, коррекция M; уменьшение не ниже 2.
- Тесты Go запускать с `-vet=off`, если исходные ошибки vet остаются; отдельно запускать штатную команду и сообщать результат.

## Приоритеты проверки

1. Невалидный последний элемент не должен оставлять напечатанную первую часть — проверка до исполнения.
2. Недопечатанный/неизвестный результат не превращается в успех или автоматическую повторную отправку.
3. Кириллица, неподдерживаемый символ и длинная строка не должны тихо теряться.
4. Пределы декодирования изображений и итогового растра проверяются до больших выделений памяти.
5. Конкурирующие чтение/продажа/печать/отключение не перемешивают параметры общего драйвера.

## Журнал

- Исходное состояние: Go `go test ./...` не проходит vet из-за `%s` для `int` и `%w` в `Sprintf` в `atol.go`. Эти строки не исправлять только ради проверки.
- Решение: существующие checkout используются согласно разрешению на локальные изменения и запрету новых каталогов без согласования. Коммиты и дополнительные worktree не создаются.

- Задачи 1–3 реализованы: подготовка/контракт, сериализация драйвера, новые HTTP/Rust методы. Go-модульные проверки и 4 Rust-теста прошли; выполняется итоговая проверка.
- Решение: QR всегда использует растровый резервный путь, поскольку встроенный обработчик JSON АТОЛ не устанавливает коррекцию/версию QR. Это сохраняет согласованные параметры и содержимое, но требует поддержки пикселей даже на ККТ со штатным QR.
- Решение: нефискальный результат проверяется через QueryData состояния, а не CheckDocumentClosed (по документации последний предназначен для фискальных документов).
- Диагностика: реальный ValidateJson 10.10.7.0 молча принимает неизвестные типы. Встроенный JS в библиотеке подтверждает отдельные ветки text/barcode/pixels и отсутствие else для неизвестного типа. Проверка возможностей усилена: корректный образец должен приниматься, а неправильное обязательное поле — отклоняться кодом 501. Пробная печать не используется.

- Итог: реализованы все четыре задачи; независимое ревью не выявило блокирующих замечаний.
- Дополнительные регрессии: непарные Unicode-суррогаты отклоняются до печати; потеря связи при проверке после исполнения сохраняет состояние `unknown`; лимит QR-растра проверяется до выделения изображения.
- Финальная проверка: `go test -vet=off -race ./...` и сборка Go в `/tmp/corex-kkt-printing-check` прошли. Штатный `go test ./...` по-прежнему останавливается на двух исходных замечаниях vet. Линкер race-сборки macOS выдаёт предупреждение LC_DYSYMTAB, тесты завершаются успешно.
- Проверка ValidateJson установленным ДККТ 10.10.7.0 (`GOARCH=amd64 CGO_ENABLED=1`, Rosetta) прошла без подключения к ККТ и без печати.
- `cargo check` и `cargo test --lib` прошли: 15 тестов, включая 4 проверки нового контракта. Форматирование затронутых файлов и `git diff --check` проверены.
- Ограничение проверки: физическая печать, отрезчик, сканирование QR и стыки растровых полос требуют оборудования. Совместимость всех моделей/версий не объявляется проверенной; неизвестные необходимые возможности приводят к понятной ошибке.
- Изменения оставлены локально без коммитов; поставляемый `libs/kkt` не заменён. Правила эксклюзивного доступа к ККТ и лицензии встроенных ресурсов описаны в документации.
